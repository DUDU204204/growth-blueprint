# SOP Template — תבנית נוהל עבודה מתועד

> כל משימה שחוזרת על עצמה ≥3 פעמים בשנה — צריכה SOP. בלי SOP, התפקיד נשאר חבוי בראש של היזם, ואי אפשר להאציל.

## מה זה SOP
**S**tandard **O**perating **P**rocedure — מסמך 1-3 עמודים שמתאר משימה בצורה שאדם אחר יכול לבצע **בלי לשאול אותך 5 שאלות**.

## למה SOPs קריטיים
1. **מאפשרים האצלה אמיתית.** "תעשה X" בלי SOP = 50% מהפעמים תקבל משהו אחר.
2. **משחררים את היזם מ-"זכרון מוסדי".** כל מה שבראש = bottleneck.
3. **מאפשרים הסקלה.** עובד חדש לומד בלי שעות הדרכה.
4. **מאפשרים מכירה של העסק.** עסק עם SOPs = יותר שווה ב-30-50% מאותו עסק בלי.

## כלל ברזל — מתי לכתוב SOP

לפי **3 השאלות:**
1. האם המשימה חוזרת ≥3 פעמים בשנה? **כן** → SOP.
2. האם זה משהו שמישהו אחר יכול לבצע (טכנית)? **כן** → SOP.
3. האם זה לוקח לי >30 דק' בכל פעם? **כן** → SOP.

**אם 3/3 — SOP חובה.**

## מבנה SOP — 8 שדות

### 1. **כותרת + סיווג**
```
SOP — [שם המשימה]
תפקיד אחראי: [Sales / Operations / Marketing / ...]
תדירות: [יומי / שבועי / חודשי / לפי טריגר]
זמן ממוצע: [N דק']
גרסה: 1.0 | תאריך עדכון: YYYY-MM-DD | בעלים: [שם]
```

### 2. **תכלית** (פסקה אחת)
*"למה אנחנו עושים את זה? מה הביזנס-וויל?"*

לא הוראה. **למה.** עובד שמבין למה — מבצע טוב יותר ויכול להתאים שיפוטים בקצוות.

דוגמה: *"מטרת השיחה היא לסנן לידים שעוברים אבחון, ולוודא שמי שמגיע ל-30 דק' של זמן יקר של הבעלים — באמת מתאים. כל ליד שלא מתאים = 30 דק' אבודות + תחושת אכזבה אצלו."*

### 3. **טריגר** (מתי הפעולה מתחילה)
*מה גורם לזה לקרות? לא רק "כל יום שני" — אלא הסיבה לפעולה.*

- **טריגר לקוח:** "ליד מילא טופס בדף Y"
- **טריגר זמן:** "כל יום שני 09:00"
- **טריגר אירוע:** "לאחר פגישת ייעוץ"
- **טריגר נתון:** "כאשר ROAS < 1.5 במשך 3 ימים רצופים"

### 4. **קלט נדרש** (מה צריך לפני שמתחילים)
רשימה ברורה של כל מה שצריך להיות זמין. אם משהו חסר — לעצור ולשאול.

```
קלט:
✓ פרטי הליד מהטופס (שם, טלפון, מייל, תיאור עסק)
✓ גישה ל-CRM (TickTick — login: [סוד])
✓ תבנית מייל (קישור)
✓ זמינות לפי לוח השנה של הבעלים
```

### 5. **שלבים** (Step-by-step)

מספור ברור. **כל שלב = פעולה אחת.** אם שלב מכיל "ו...ו...ו" = לפצל.

דוגמה (לקוחה מ-SOP "שיחת קו ראשון"):
```
1. פתח את ה-CRM ועדכן את סטטוס הליד ל-"בטיפול".
2. צלצל למספר שבטופס. אם לא עונה — שלח SMS לפי תבנית [קישור].
3. כשענה — פתח עם הסקריפט [קישור]. *לא מאלתר.*
4. עבור על 4 שאלות הסינון (ראה סעיף 6).
5. אם **3/4 או יותר חיוביות** → שלח מייל זימון ל-30 דק' (תבנית A).
6. אם **<3/4** → תודה, אומר "לצערי לא נראה לי שזה מתאים כרגע", שלח מייל פולואפ (תבנית B).
7. עדכן ב-CRM: "התקיים — מתאים" / "התקיים — לא מתאים" / "לא ענה".
8. אם **מתאים** → קבע פגישה ביומן + שלח ללקוח Zoom link + תזכורת 24 שעות לפני.
9. הוסף הערה ב-CRM על "מצב ראשוני" (3-4 שורות).
```

### 6. **קריטריונים** / **מבחנים** (אם רלוונטי)

לכל החלטה בתהליך — מה הקריטריון?

```
4 שאלות סינון:
1. תקציב חודשי לליווי ≥ ₪3,000? (כן/לא)
2. עסק פעיל ≥ 12 חודשים? (כן/לא)
3. יש לפחות מוצר/שירות אחד שמוכר? (כן/לא)
4. נכון להיום, רוצה להתחיל לעבוד תוך ≤ 30 יום? (כן/לא)

מתאים = 3/4 או יותר חיוביות
```

### 7. **דוגמאות / Edge Cases** (מה לעשות כש...)

מה שלא הולך לפי ה-default. **זה מה שמבדיל SOP טוב מ-SOP אקדמי.**

```
מה לעשות אם...
- הליד אומר "אשלם כשתעבוד" → "הליווי מתחיל בתשלום ראשון. אם אינך מוכן להתחייב כעת, אשלח לך פולואפ בעוד שבוע."
- הליד מבקש להוריד מחיר ב-50%+ → "הליווי הוא תוכנית מובנית. אם המחיר לא מתאים — אולי הקורס שלנו במקום [קישור] מתאים יותר."
- אין מענה אחרי 3 ניסיונות → סגירה ל-"Cold". העברה ל-mailing list לפולואף 30 יום.
- הליד מגיע מ-ערוץ לא מסומן ב-UTM → לסמן ידנית ב-CRM "מקור: [תיאור]" + לשאול איך מצא אותנו.
```

### 8. **פלט / מסירה** (מה התוצר)

```
פלט:
- רישום ב-CRM (סטטוס + הערה)
- אם מתאים: פגישה ביומן + מייל אישור ללקוח + Zoom link
- בסוף השבוע: דוח שבועי לבעלים עם מספר השיחות + יחס סינון
```

## איך כותבים SOP בפעם הראשונה (45 דק')

### שיטה 1 — Loom Recording
1. **בפעם הבאה שאתה מבצע את המשימה** — הקלט את עצמך עושה אותה ב-Loom.
2. תוך כדי — דבר רם **למה** אתה עושה כל צעד.
3. שלח את ההקלטה לתמלול (או ל-VA).
4. הם הופכים את ההקלטה ל-SOP draft.
5. אתה סוקר 10 דק'.

### שיטה 2 — RPM Time-Block
1. הקצא 45 דק' חסומים. אין הסחות.
2. כתוב את ה-SOP מתבנית.
3. **בדוק בעצמך** — האם מישהו אחר היה יכול לבצע בלי לשאול אותי?

### שיטה 3 — מעבד את המוצר (לעובד קיים)
1. בקש מהעובד שמבצע את המשימה: *"כתוב SOP של איך אתה עושה X. אני אסקור."*
2. אם העובד לא יכול לכתוב SOP — סימן שגם הוא לא יודע בדיוק מה הוא עושה. **בעיה**.

## טיפים מצטברים

1. **לא יותר מ-3 עמודים.** SOP של 10 עמודים לא נקרא, וזה גרוע מ-SOP של 0 עמודים.
2. **לכל SOP — קישור לקלט/פלט בפועל.** טופס, תבנית מייל, link ל-CRM. לא תיאור — קישור.
3. **תבנית סטנדרטית לכל ה-SOPs בעסק.** עקביות = פחות חיכוך.
4. **גרסה + תאריך עדכון** — חובה. אחרת ה-SOP מתיישן בלי שיודעים.
5. **מי שמבצע — יכול להציע עדכון.** SOPs לא קודש. הם מתעדכנים מהשטח.
6. **תיקיה ייעודית ב-Drive** — `[SOPs]`. תת-תיקיות: Sales / Operations / Marketing / Onboarding / Finance.
7. **Master Index Sheet** — Google Sheet עם רשימת כל ה-SOPs + קישור + בעלים + תאריך עדכון.

| משימה | תדירות | חוסכת... |

## הבעיה הקלאסית
**"אין לי זמן לכתוב SOP."** = אין לי זמן לעצור את הריצה כדי להבין למה אני רץ.

**ROI של SOP:**
- כתיבה: 45 דק' חד-פעמית.
- חיסכון: 30 דק' × 50 פעמים/שנה = 25 שעות.
- ROI: 33x.
