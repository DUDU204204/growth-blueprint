# Checklist — איפיון אתר מכירתי

> רשימת בקרה מהירה. אם ❌ ב-3+ פריטים בשכבה — לעצור ולטפל לפני המשך.

## לפני שמתחילים
- [ ] יש תמלול/סיכום של פגישת גילוי ראשונית
- [ ] הלקוח הגדיר KPI עסקי (לידים/חודש? MRR? שיחות מכירה?)
- [ ] זוהה budget + דדליין ריאליסטיים
- [ ] הלקוח התחייב להעביר חומרים (לוגואים, עדויות, case studies)

## שכבה 1 — Discovery
- [ ] 1-3 אווטרים מוגדרים עם 4 ממדים (חיצוני/יומיומי/רגשי/שאיפות)
- [ ] ארכיטיפ לכל אווטאר (מנהיג/חוקר/מדווח/גיבור סרבן)
- [ ] הכאב הראשי מנוסח במילות הקהל + **שם ממותג** לכאב
- [ ] שלב מודעות (Schwartz): Unaware / Problem / Solution / Product / Most
- [ ] Market Sophistication Level (1-5) + ניתוח 5+ מתחרים
- [ ] KPIs עסקיים ברורים (3-5)

## שכבה 2 — אסטרטגיה
- [ ] USP עבר 3 מבחנים (ברור מיד / מתחרה לא יכול לומר / ספציפי)
- [ ] XYZ: "אני עוזר ל-X להשיג Y בלי Z" — 2 ניסוחים
- [ ] Value Stack של 4-8 רכיבים, סה"כ > המחיר הסופי
- [ ] 11 הקריטריונים למוצר סומנו (✅/⚠️/❌)
- [ ] אין ❌ ב-3+ קריטריונים (אחרת — לדון עם הלקוח לפני המשך)
- [ ] תבנית הצעה נבחרה (תמורה / טרנספורמציה / אלטרנטיבה)
- [ ] גישת מכירה: PUSH או PS

## שכבה 3 — מפת אתר
- [ ] רשימת עמודים מינימליסטית (5-10 מקסימום)
- [ ] כל עמוד במרחק ≤3 קליקים מהבית
- [ ] **טבלת Exit-Paths מלאה**: CTA ראשי + משני + לאן-אחרי-פוטר לכל עמוד
- [ ] אין dead-ends — כל עמוד יש לו exit
- [ ] מפות flow ל-2-3 אווטרים (מקור → נחיתה → המרה)
- [ ] עמודי LP ייעודיים לקמפיינים ממומנים (לא שליחה לבית)

## שכבה 4 — מבנה עמוד
- [ ] לכל עמוד מכירתי: 10 sections הבסיס (Hero → Hook → Story → Pain → Solution → Offer → Proof → FAQ → CTA → Footer)
- [ ] CTA ראשי גלוי באיפיון של ה-Hero (בלי גלילה)
- [ ] טבלת section-level exits — לכל section מטרה + CTA + exit
- [ ] עמודים לא-מכירתיים (על, בלוג, צור קשר) — יש להם exit-path גם הם
- [ ] הגדרות מובייל (CTA במסך ראשון, sticky CTA, כפתורים 44x44+)

## שכבה 5 — קופי
- [ ] טון מוגדר ב-3 תארים + Don'ts
- [ ] 5+ עקרונות בראשית עם דוגמאות קונקרטיות
- [ ] הוראה מפורשת ל"קריא ברפרוף"
- [ ] 2-3 פתיחות נבחרו מתוך ה-11
- [ ] 3-5 headlines חלופיות לכל עמוד מכירתי
- [ ] 5-7 CTA copies תוצאתיים
- [ ] מילון ז'רגון של הלקוח (do/don't)

## שכבה 6 — UI/UX + אינטראקטיביות + מובייל
- [ ] F/Z pattern מיושם
- [ ] widgets אינטראקטיביים מוגדרים (quiz/chat/calc) — **כל אחד עם out-path**
- [ ] Sticky WhatsApp float / CTA בתחתית מובייל
- [ ] Performance budget: <1.5s טעינה במובייל
- [ ] Exit-intent popup (רק בדסקטופ; או scroll 70%+)
- [ ] טפסים מותאמי מובייל (inputmode, autocomplete)
- [ ] Micro-interactions מוגדרים (hover, loading, success)
- [ ] QA על מכשיר אמיתי (לא רק DevTools)

## שכבה 7 — מיתוג ועיצוב
- [ ] Brand Voice: 3 תארים לטון + Don'ts
- [ ] פלטת צבעים (Primary / Secondary / Accent / Neutrals)
- [ ] ניגודיות WCAG AA מינימום 4.5:1
- [ ] טיפוגרפיה: פונט ראשי + משני שתומכים עברית + היררכיה
- [ ] 3-5 רפרנסים של אתרים שאוהבים (+ "כן מזה" / "לא מזה")
- [ ] ויזואלים: סגנון צילום/אייקונים/אילוסטרציות

## שכבה 8 — CRO ומדידה
- [ ] **UTMs + hidden fields** בכל טופס (utm_source/medium/campaign/term/content + gclid + fbclid + landing_page + referrer + session_id)
- [ ] החלטה על DB: קיים → חיבור; אין → **הנחיה מפורשת ליצור** (ברירת מחדל: Supabase)
- [ ] Schema טבלת leads (מינימום 12 שדות)
- [ ] חיבור אוטומטי ל-CRM (webhook)
- [ ] GA4 events מוגדרים
- [ ] Meta Pixel / Google Tag (אם יש קמפיינים)
- [ ] Microsoft Clarity מותקן
- [ ] CMP (Cookiebot וכדומה) ל-GDPR
- [ ] Schema markup (Organization / Service / FAQ / Review / Breadcrumb)
- [ ] Double opt-in לניוזלטר (חוק הספאם הישראלי)
- [ ] Success page נפרדת אחרי שליחת טופס
- [ ] KPIs + תבנית דשבורד שבועי

## לפני הגשה — General
- [ ] **חוק הזהב: no cul-de-sacs** — כל עמוד + כל section + כל widget יש להם exit?
- [ ] המסמך **קריא ברפרוף** (bold, bullets, כותרות ביניים)
- [ ] המסמך נשמר בתיקיית הפרויקט / בפורמט המסמכים של המשתמש (RTL + פונט עברי)
- [ ] משימות פתוחות ללקוח רשומות בסוף (מה צריך להעביר)
